# PH-08 — центр сповіщень

Прямий запит від 19.10.2026: глобальний дзвіночок; призначення завдання, згадка у коментарі, близький дедлайн, особисте повідомлення; перехід до потрібної картки або чату. [Концепт](concepts/NOTIFICATIONS_AND_CHAT_CARDS.md) згенерований до коду вбудованим image_gen. [Протокол](PH08_NOTIFICATIONS_RESULTS.json).

## Поведінка

Дзвіночок біля логотипу доступний на кожній сторінці. Значок показує тільки непрочитані, після 99 — «99+». Панель має «Усі», «Непрочитані», окрему позначку прочитання, «Прочитати всі» й попередні сторінки по 50. Список оновлюється кожні 5 секунд, також при відкритті та діях. Відкриття панелі саме по собі не читає всі події. Клік події читає її та відкриває ціль; перехід зі зміненого редактора вимагає збереження/відкидання за чинним механізмом чернеток.

- Призначення: іншому користувачу при створенні або зміні відповідального; повторне збереження того самого призначення та призначення собі не створюють зайвих подій.
- Згадка: `@email` учасника, без урахування регістру, з перевіркою меж адреси. У коментарях є вибір учасника та «@ Згадати». Повтор адреси в тексті не дублює подію; редагування додає події тільки новим згаданим. Одна подія на коментар/одержувача, власні згадки та сторонні адреси пропускаються.
- Дедлайн: активні неархівовані картки, призначені одержувачу, зі строком сьогодні або завтра. Календар цього етапу — UTC серверного `TimeProvider`. При запиті списку одна атомарна SQL-операція створює відсутні нагадування; один запис на картку/одержувача/дату. Закритий клієнт не опитується; нагадування готується при наступному зверненні. Перенесення строку або зміна відповідального робить старе нагадування недоступним.
- Повідомлення: іншому учаснику діалогу в одній транзакції з текстом. Повтор надсилання з тим самим ID не дублює подію. Читання історії чату також читає відповідні сповіщення до отриманого курсора.

Події зберігаються в MSSQL після закриття клієнта. Вихід стирає список із пам’яті; пізня відповідь старого сеансу не повертає його. Помилка сервера показується в панелі; опитування повторюється.

## Доступ і схема

Сьома міграція `20261019192346_NotificationCenter` додає `Notifications`: одержувач, необов’язковий автор події, тип, ключ дедуплікації, ID цілей, дата дедлайну, створення й прочитання. Разом **13 доменних таблиць**. Унікальний `(UserId, EventKey)`, індекс `(UserId, ReadAtUtc, Id)`, усі FK `NoAction`. Назви карток і тексти повідомлень не копіюються в історичний знімок: сервер формує DTO за чинним доступом. Цілі без FK дозволяють зберегти безпечний запис після видалення ресурсу. Видалений/архівований ресурс або відкликаний доступ дає нейтральне «Сповіщення недоступне» без приватної назви та ID переходу.

Власність перевіряється для кожного читання/відкриття/позначення; чужий ID дає 404, анонімний — 401. Повторна перевірка цілі виконується при відкритті, кінцевий API картки/чату також авторизує запит. «Прочитати всі» використовує `throughId`, тому пізніші події не губляться. Очищення аккаунта прибирає його власні сповіщення й анонімізує автора в чужих; семиденне відновлення зберігає історію. Downgrade з історією відхиляється SQL 50007.

| Метод | Шлях | Дія |
| --- | --- | --- |
| GET | `/api/notifications?unreadOnly=false&beforeId=…` | Сторінка, загальна кількість непрочитаних і верхній курсор |
| POST | `/api/notifications/{id}/open` | Перевірити ціль, прочитати й повернути перехід |
| POST | `/api/notifications/{id}/read` | Прочитати власну подію |
| POST | `/api/notifications/read-all` | Прочитати до `throughId` |
