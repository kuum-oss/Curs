# PH-08 — чек-листи в картках

Доповнення від 19.10.2026: погоджений перший етап — пункти з прапорцями, додавання та перестановка, прогрес «3 з 5». Спочатку створено [згенерований концепт](concepts/CHECKLIST_CONCEPT.md) на основі чинного інтерфейсу, після нього — код. Сповіщення й WIP-ліміти до цього доповнення не входять.

## Використання

Відкрийте або створіть картку. Між описом і коментарями розташований «Чек-лист»: введіть пункт і натисніть «＋ Додати». Текст редагується на місці, прапорець змінює виконання, × прибирає пункт. Для порядку перетягніть ручку з крапками зліва або натисніть ↑ / ↓. Неприпустимі напрямки на першому й останньому пунктах вимкнені.

Лічильник і бірюзова смуга редактора оновлюються одразу. Усі зміни є чернеткою до загальної кнопки **«Зберегти»** й записуються разом з іншими полями картки. Якщо новий текст ще не додано, збереження просить натиснути «Додати». Закриття зміненого редактора пропонує продовжити або відкинути чернетку. На дошці видно збережену кількість виконаних пунктів і прогрес; порожній список прихований.

Робочі ліміти: один список на картку, до 100 пунктів, від 1 до 300 UTF-16 одиниць тексту; порожні й пробільні назви відхиляються, зовнішні пробіли обрізаються. Це уточнення реалізації, а не вимога початкового ТЗ. Обмеження створення/видалення карток не забороняє редагувати чек-лист наявної картки. Виконаний текст приглушений; кнопки ↑/↓ доповнюють ручку концепту.

## API та збереження

Нові маршрути не потрібні. `POST /api/boards/{id}/cards` та `PUT /api/cards/{id}` приймають `checklist`: масив `id`, `title`, `isCompleted`. Порядок масиву визначає позиції 0…N−1. Відсутній або null `checklist` залишає старий список для сумісності; `[]` явно очищує його. `GET /api/cards/{id}` повертає пункти з `position`; короткий DTO містить `checklistCompleted` і `checklistTotal`.

Сервер перевіряє членство, версії дошки й картки, ліміти, текст, унікальність непорожніх ID та належність наявного ID цій картці. Чек-лист і поля зберігаються однією транзакцією. Застаріле збереження дає 409; клієнт повідомляє про конфлікт і зберігає власну чернетку. Узгоджене читання деталей/підсумків використовує транзакцію; підрахунки для сторінки карток виконуються пакетно.

Шоста міграція `20261019182649_CardChecklists` додає `ChecklistItems(Id, CardId, Title, IsCompleted, Position)` та індекс `(CardId, Position)`: **12 доменних таблиць**. Попередні 11 таблиць міграція не змінює. FK має `NoAction`; видалення картки, колонки, дошки або остаточне очищення особистої дошки явно прибирає пункти. Архів, семиденне відновлення та передача спільної дошки зберігають список. Downgrade з пунктами заборонений SQL 50006.

## Перевірки

- **157 тестів із реальною MSSQL: 0 помилок, 0 пропусків.** Додано п’ять серверних, одну міграційну та три клієнтські перевірки; наявний тест відновлення аккаунта доповнений збереженням/очищенням пунктів. Охоплено валідацію без часткового запису, чужі ID, конкурентний запис, дозволи, архів, видалення, порядок, відкидання, конфлікт і вихід під час запиту.
- Release та нативна публікація без помилок і попереджень. EF не має незбережених змін моделі.
- **17 HTTP-запитів** production Docker API: 3/5, зміна тексту/стану/порядку, 409, невалідний текст без зміни версії, узгоджений прогрес і сумісність старого клієнта.
- CUA в Avalonia: текст, позначки, додавання шостого пункту, видалення, ↑, збереження, повторне відкриття, попередження про чернетку й відкидання. Docker API підтвердив остаточні 5 пунктів, 3 виконані, послідовні позиції та однаковий прогрес на дошці.
- Керування **мишою** через CUA заблоковане помилками `noWindowsAvailable` / `cgWindowNotFound`. **Перетягування, збереження й повторне відкриття вручну перевірив і підтвердив користувач.** Це окремий ручний доказ, а не автоматичний тест.
- Обидва Docker-контейнери healthy, у БД 6 міграцій та 12 таблиць. Перша збірка зупинилася через заповнений диск; після очищення невикористаного кешу збірок повторна збірка успішна. Робочий том збережений. Чотири захищені demo на місці; випадковий перевірочний аккаунт із власною дошкою прибраний після виходу.
