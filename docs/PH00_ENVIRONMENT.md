Дата: 11.10.2026. Статус: перевірку пройдено. Завершено о 23:04:57 за часом Asia/Riyadh (UTC+03:00).

## 2. Метод перевірки

1. Завантажити образ SQL Server 2022 для `linux/amd64`.
2. Запустити ізольований тестовий контейнер з окремим іменованим volume та випадковим локальним паролем із `.env`.
3. Дочекатися фактичного SQL-підключення через клієнт усередині контейнера.
4. Прочитати версію сервера та виконати `SELECT 1`.
5. Створити тестову БД і таблицю, записати контрольне значення.
6. Перезапустити контейнер, повторно прочитати значення та перевірити результат.
7. Зафіксувати digest образу, результат і час перевірки; видалити лише створені цією пробою контейнер та volume.

Пароль передано через локальний `.env`, не включено до документації чи журналу перевірки. Використано лише тестовий набір, дані інших контейнерів не змінювалися. Образ і `.env` залишаються локально для подальшої розробки; `.env` ігнорується Git і має права доступу `600`.

## 3. Межі підтвердження

- Підтверджено доступність MSSQL та базових типів даних на цьому Mac через емуляцію.
- Перевірено збереження після перезапуску контейнера. Відновлення після його видалення/повторного створення та приймання повного застосунку входять у PH-07–PH-08.
- SQL-служба виконувала пробу в окремому Compose-проєкті `kanban-ph00-57df3aa10d`, тому робочий volume KanbanBoard не наповнювався тестовими даними. Тестовий сервер після проби зупинено й видалено.
- API, EF-міграції, 20 одночасних користувачів, ліміт 2 секунди та GUI ще не перевірені.
- Microsoft не підтримує SQL Server в емуляції; результати не перетворюють це середовище на офіційно підтримуване. [Офіційне обмеження](https://learn.microsoft.com/en-us/sql/linux/containers/deploy?view=sql-server-ver16).

## 4. Повторний запуск БД для PH-01

Локальний `.env` уже створений. З кореня проєкту:

```sh
docker compose config --quiet
docker compose up -d sqlserver
docker compose ps sqlserver
```

Дочекатися `healthy`. Локальний SQL-порт — `localhost,3038`; API всередині Compose використовуватиме `sqlserver,1433`. Пароль береться з локальної конфігурації, не з цього документа.

Повний запуск API недоступний до створення `KanbanApi` і Dockerfile. Для штатної зупинки зі збереженням робочих даних — `docker compose down` без `-v`.
