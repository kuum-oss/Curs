# PH-08 — привітальний екран і «Запам’ятати мене»

Доповнення за референсом і прямим запитом користувача від 17.10.2026. Попередні [вимоги](REQUIREMENTS.md), [автентифікація](PH02_AUTHENTICATION.md) та [відновлення аккаунта](PH08_ACCOUNT_ICON.md) залишаються чинними.

## Інтерфейс

Ліва частина містить логотип, «Плануйте. Співпрацюйте. Досягайте.» та три можливості: гнучкі дошки, командна робота, прогрес. Права — білу форму з полями, кнопкою показу/приховування пароля, тумблером «Запам’ятати мене» та переходом до реєстрації. Нижче — декоративна Kanban-дошка, створена штатними елементами Avalonia; вона не видає себе за робочі кнопки чи дані користувача. Форми мають прокручування при недостатній висоті вікна. Реєстрація має окремий пояснювальний текст, показ пароля скидається при переході між формами та після спроби входу.

## Збереження та вихід

- Типово тумблер вимкнений: закриття застосунку не залишає збереженого входу.
- Увімкнений тумблер зберігає **останній успішний сеанс**: токен та email. Пароль не зберігається.
- macOS використовує локальну В’язку ключів через Security.framework. Одна позиція на адресу налаштованого API; токен не потрапляє до файлів налаштувань, журналів, аргументів процесу або Git. Синхронізація iCloud не вмикається.
- Звичайне закриття/перезапуск зберігає сеанс. Під час запуску спочатку перевіряється `GET /api/auth/me`; робочий простір відкривається лише після успішної перевірки сервера.
- «Вийти» видаляє збережений вхід і повертає привітальний екран. Тумблер у цьому вікні можна вимкнути та увійти іншим аккаунтом. Після виходу автовхід у попередній аккаунт не запускається.
- Вимкнення тумблера прибирає збережений вхід. Новий успішний вхід або зміна пароля/email замінює попередні дані одного сеансу.
- JWT, як і раніше, діє **24 години**; прострочений чи відкликаний токен видаляється й показується звичайний вхід. Пароль не використовується для прихованого повторного входу; безстроковий refresh не додавався.
- При недоступному сервері збереження залишається для кнопки повторної спроби; користувач може вимкнути тумблер і обрати ручний вхід. Помилка доступу до В’язки ключів показується зрозумілим повідомленням, ручний вхід працює.
- Пізня відповідь після виходу не відновлює старий сеанс. Планування видалення аккаунта та 401 у робочих запитах також очищають запам’ятаний вхід; серверні правила семи днів і захист чотирьох demo не змінюються.

Постійне сховище підключене у композиції macOS. Інші ОС і автоматичні тести типово використовують сховище в пам’яті; для них не заявляється перевірений постійний автовхід.

## Перевірки

Сім нових тестів перевіряють opt-in, збереження після Dispose/закриття, валідацію перед показом дошок, вихід/зміну аккаунта, 401, offline/retry, пізню відповідь, ротацію токена/email та недоступне сховище. Разом із попередніми тестами форм входу й видалення — 16 успішних тестів у цільовому запуску.

Окремий нативний стенд на цьому Mac створив випадковий власний запис із вигаданим не-JWT значенням, перевірив читання, оновлення й видалення через той самий клас Security.framework. Стенд завершився з кодом 0; жодні чужі позиції В’язки ключів не переглядалися й не змінювалися.

Через CUA перевірено у справжньому `.app`:

1. Вхід як Анастасія з увімкненим тумблером → закриття → запуск → автоматично її дошки й ім’я.
2. «Вийти» → привітальний екран із порожніми полями.
3. Тумблер вимкнено → вхід як Олена → закриття → запуск → привітальний екран без автовходу.
4. Показ/приховування на вигаданому значенні пароля, перехід до реєстрації зі скиданням поля, огляд обох форм скриншотами.

Існуючі demo-аккаунти й дошки не редагувалися та не видалялися. Після перевірки сховище реального входу порожнє, тумблер вимкнений. Нативний пакет оновлено. Паролі та JWT не включені до цього документа.
