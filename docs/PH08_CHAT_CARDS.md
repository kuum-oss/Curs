## Поведінка

У відкритій переписці натисніть «Поділитися карткою», виберіть доступну активну дошку, знайдіть картку за назвою, виберіть її та натисніть «Поділитися». Завантажуються всі сторінки карток вибраної дошки. У повідомленні з’являються назва, дошка/колонка й «Відкрити картку». Посилання відкриває існуючий редактор із захистом незбережених змін. Текст, набраний у полі повідомлення, зберігається окремою чернеткою; надсилання картки його не відправляє й не очищує.

Доступ перевіряється для відправника при надсиланні, а для кожного читача — при завантаженні історії та повторно при відкритті. **Надсилання не додає учасника до дошки.** Отримувач без доступу бачить нейтральну плитку, без назви дошки, приватного заголовка та ID цілі. Відкриття після відкликання відхиляється навіть із раніше завантаженої плитки. Старі заголовки у вже показаній історії оновлюються при повторному відкритті розмови; опитування нових повідомлень не переписує старі плитки. «Перевірити доступ» дозволяє повторити спробу після явного надання членства.

Видалена або архівована картка/дошка не відкривається, повідомлення залишається в історії. Це посилання на чинний ресурс, без історичного знімка полів. Повідомлення доступні лише двом учасникам чату; нова розмова, як і раніше, потребує спільної дошки. Скасування вікна нічого не надсилає. При втраті відповіді вибір і стабільний ID повідомлення зберігаються для повтору без дублікатів. Вихід очищує вибір і приватні дані, пізня відповідь їх не відновлює.

## API та зберігання

`POST /api/chats/{id}/messages`: необов’язкове `sharedCardId` поряд із `clientMessageId` і `text`. Порожній текст допускається лише з посиланням; сервер використовує «Поділилися карткою». Звичайний чат сумісний із попереднім контрактом. Повтор із тим самим ID порівнює відправника, нормалізований текст і картку; інший вміст дає 409. Запис повідомлення й сповіщення відбувається в одній транзакції.

`GET /api/chats/{id}/messages/{messageId}/card` перевіряє учасника діалогу, належність повідомлення та актуальний доступ. Повертає `SharedCardDto(cardId, boardId, title, context, canOpen)` або нейтральний 404. Історія містить nullable `sharedCard`: за відсутності доступу обидва ID null. Метадані сторінки завантажуються пакетно, без окремого запиту на кожне повідомлення; читання доступу узгоджене транзакцією.

Восьма міграція `20261019200219_ChatCardSharing` додає nullable `DirectMessages.SharedCardId` (без FK до картки). Кількість таблиць лишається **13**; старі повідомлення та робочий volume збережені. Downgrade з посиланнями заборонений SQL 50008.

## Перевірки

**175 тестів із реальною MSSQL: 0 помилок, 0 пропусків.** Додано 5 серверних, 1 міграційний і 3 клієнтські. Перевірено конкурентний повтор без дублювання повідомлення/сповіщення, актуальну назву, доступ відправника й одержувача, відсутність неявного членства, відкликання/повторне надання, чужі ID, архів/видалення, старі сторінки, невалідні запити, downgrade, збереження чернетки, втрату відповіді та вихід під час запиту. Release і нативна публікація без попереджень/помилок; EF не має змін поза міграцією.

31 production HTTP-запит перевірив обмін, точну ціль, дублікати, відкликання й повторний доступ, анонімний/сторонній запит. Повторна регресія центру сповіщень — 26 успішних запитів. Нативний CUA: пошук/вибір, третє надіслане повідомлення, збережена чернетка до й після навігації, правильний редактор; другий аккаунт, відмова для кешованого посилання після відкликання, нейтральна історія після повторного відкриття, вихід. Надіслане повідомлення додатково звірено через API.

3 власні випадкові аккаунти й їхня дошка прибрані; 4 захищені demo збережені. API/SQL healthy, 8 міграцій, 13 таблиць, той самий `kanbanboard_sqlserver-data`.
