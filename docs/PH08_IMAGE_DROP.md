# PH-08 — виправлення PNG macOS та перетягування обкладинки

Виконано 16.10.2026 за повідомленням користувача про відмову завантажити скриншот і запитом на drag-and-drop фото. Вимога — [FR-IMAGE-06](REQUIREMENTS.md#36-зображення); загальна реалізація — [PH08_DESKTOP](PH08_DESKTOP.md).

## Як користуватися

Перетягніть один файл JPG, PNG або WEBP з Finder на потрібну картку дошки або на область фото у відкритому редакторі. Область підсвічується під час наведення. Обкладинка зберігається одразу, оновлюються превью й повне зображення; незбережені назва та опис залишаються чернеткою. Кнопка «Змінити фото» також працює.

Для нової картки спочатку потрібно зберегти її. Ліміт — 5 МіБ. Кілька файлів і папки відхиляються. Непідтримуваний вміст, пошкоджене зображення та перевищення ліміту не замінюють попереднє фото. Звичайне перетягування карток і колонок використовує наявні обробники переміщення.

## Причина та зміни

Обидва реальні PNG повністю декодувалися, але libpng повідомляв `iCCP: extra compressed data`. Сервер трактував будь-яке попередження як пошкодження. Тепер лише це конкретне попередження метаданих для PNG дозволене; усі інші попередження, винятки декодера, перевірки формату, розміру та кількості пікселів залишаються чинними. Оригінальні байти зберігаються, превью генерується окремо.

Клієнт використовує файлові дані Avalonia `DataFormat.File`, спільне читання з межею 5 МіБ і той самий захищений маршрут завантаження. До читання фіксуються картка, дошка та їхні версії. Перехід, вихід і скасування не можуть перенаправити старий файл до іншої картки або нової сесії.

Синтетичний регресійний PNG містить вбудований sRGB-профіль із додатковими байтами після стисненого потоку. Особисті скриншоти та витягнутий профіль монітора до Git не додавалися.

## Перевірки

[Машинний протокол](PH08_IMAGE_DROP_RESULTS.json) містить лічильники й шість нових тестів:

- повне декодування PNG із попередженням ICC, оригінал і превью 480 × 320;
- відхилення пошкодженого CRC піксельних даних навіть за дозволеного попередження ICC;
- HTTP-завантаження такого PNG, збереження попередньої обкладинки й версій після невдалої заміни;
- зміна лише цільової картки без відкриття редактора, відхилення понад 5 МіБ;
- збереження чернетки редактора та відхилення іншої цільової картки;
- вихід і новий вхід під час читання файла без запізнілого завантаження.

Усього: **111 пройдено, 0 помилок, 0 пропусків**, реальна MSSQL. Release solution — **0 помилок і 0 попереджень**. Docker API перебудовано й запущено зі збереженням робочого SQL volume. Вихідний проблемний PNG завантажено з HTTP 200, повернутий оригінал побайтово збігається, превью PNG отримано; попередню обкладинку окремої тестової картки після перевірки відновлено.

У звичайному клієнті скриншот обрано через macOS picker, перевірено превью та повний перегляд. Нативний файловий жест перевірено тимчасовим стендом із реальним `IStorageFile` та робочими компонентами клієнта: отримано `Copy`, байти цільової обкладинки звірено API. Автоматизація не отримала вікна Finder, тому джерело файла надавав стенд. Користувач окремо підтвердив: «я проверил работает». Стенд і його панель не входять у застосунок та Git.

Повторити автоматичні перевірки:

```sh
scripts/dotnet.sh build Curs.sln -c Release
KANBAN_TEST_CONFIGURATION=Release python3 scripts/verify-ph01.py image-drop
scripts/package-macos.sh
```

Після оновлення потрібно перезапустити клієнт. Поточний Docker API вже містить виправлення; для іншої локальної копії застосовується звичайний `docker compose up -d --build --wait` з [інструкції запуску](DEPLOYMENT.md).
