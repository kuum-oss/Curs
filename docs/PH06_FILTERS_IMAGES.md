## Реалізовано

Пошук за назвою без урахування регістру та фільтри за пріоритетом, тегом, відповідальним і дедлайном поєднуються через AND. Символи `%` та `_` у пошуку є буквальними символами. Прострочені дати менші за локальне сьогодні, сьогодні — рівні, майбутні — більші; записи без дедлайну не потрапляють у ці три вибірки. Клієнт передає календарну дату; після локальної півночі вибірка оновлюється навіть без зміни версії дошки.

Запит починається через 300 мс після зміни пошуку/фільтрів. Попередній пошук скасовується, застарілий результат не публікується. Скидання повертає повний список. Усі сторінки завантажуються з однаковими умовами та перевіркою версії; збережені позиції не змінюються. За активних фільтрів перенесення карток недоступне, перенесення колонок працює після повного завантаження вибірки.

У редакторі доступні вибір файлу через нативний діалог macOS, завантаження, заміна й прибирання обкладинки. Нову картку спочатку зберігають, після цього додають фото. Одна обкладинка складається з незміненого оригіналу та PNG-превью зі стороною до 480 пікселів у MSSQL. На картці відображається превью, у редакторі — повний файл із збереженням пропорцій.

Файл обмежено 5 × 1024 × 1024 байтів. Формат визначається сигнатурою; назва й наданий MIME не є доказом. Дозволені лише декодери JPEG, PNG та WEBP. Перевіряються завершеність контейнера, декодовані розміри до 20 мегапікселів і 10 000 пікселів по стороні та повідомлення декодера. Пошкоджений, непідтримуваний, завеликий або застарілий запит не замінює попередню обкладинку. Ліміт усього multipart-запиту — 5 МіБ + 64 КіБ, ліміт файлу лишається 5 МіБ.

Заміна/прибирання фото, оновлення версій картки та дошки виконуються у транзакції `BoardAccess`. Доступ перевіряється за поточним членством; обмеження створення/видалення карток не забороняють редагувати фото. Чужий ресурс або відкликаний доступ дає 404, відсутній JWT — 401.

Фото отримуються через авторизований `HttpClient`; бінарні відповіді мають фактичний Content-Type, `no-store, private` та `nosniff`. Превью догружаються для видимих карток, до чотирьох мережевих завантажень одночасно. Кеш байтів прив’язаний до сесії, ID й версії картки та обмежений 8 МіБ/128 записами. Bitmap належать поточним рядкам/редактору й звільняються при заміні представлення, виході або втраті доступу. Пізня відповідь попередньої сесії не заповнює кеш.

## API

Префікс `/api`; усі маршрути захищені JWT.

| Метод і маршрут | Поля / результат |
| --- | --- |
| GET `/boards/{boardId}/cards` | `offset`, `limit`, `search`, `priority`, `tagId`, `assigneeId`, `deadline`, `today`; сторінка зі збереженим порядком і версією дошки |
| PUT `/cards/{cardId}/image` | multipart: один `File`, `ExpectedVersion`, `ExpectedBoardVersion`; 200 з новими версіями |
| GET `/cards/{cardId}/image` | Незмінений оригінал із фактичним MIME |
| GET `/cards/{cardId}/image/thumbnail` | PNG-превью |
| DELETE `/cards/{cardId}/image` | Версії у query; 204, нові версії клієнт перечитує |

Enum-параметри приймають назви; невалідні значення й дедлайн без `today` дають 400. Версії — Base64 восьмибайтового SQL rowversion. Непідтримуваний формат — 415, перевищення розміру — 413, конфлікт — 409. Навіть рання відмова Kestrel на завеликий multipart має відповідь ProblemDetails.

[Ліцензія Magick.NET](https://github.com/dlemstra/Magick.NET/blob/main/License.txt) — Apache 2.0; компоненти ImageMagick мають [власну ліцензію](https://imagemagick.org/license/). Склад і повідомлення ліцензій входять у пакет `Notice.txt`. Графічні залежності Avalonia не змінено.

Аудит NuGet 14.10.2026 виявив у транзитивному `System.Security.Cryptography.Pkcs 9.0.11` опубліковані уразливості. Пряме посилання на 10.0.13 застосовано за [офіційним повідомленням Microsoft](https://github.com/advisories/GHSA-846f-f764-76mx); збірка проходить без попереджень аудиту.

За готового SQL і локального `.env`:

```sh
scripts/dotnet.sh build Curs.sln -c Release
python3 scripts/verify-ph01.py ph06
scripts/dotnet.sh ef migrations has-pending-model-changes --project KanbanApi --no-build
scripts/dotnet.sh build KanbanApi
python3 scripts/verify-ph06-http.py
```

HTTP-скрипт сам створює JPG/PNG/WEBP та негативні фікстури у виключеному з Git TestResults, запускає API на 5046, перевіряє й прибирає випадкову `KanbanPh06_<uuid>` БД. Для GUI використати `--gui` та `KANBAN_API_URL=http://127.0.0.1:5046/`; після закриття клієнтів перервати скрипт. Секрети не записуються у фазовий протокол.

Порядок публікації: перевірки → push `ph-06` та перевірка remote HEAD → fast-forward `main`, push і перевірка remote HEAD. Наступна фаза — PH-07: Docker API та збереження даних.
