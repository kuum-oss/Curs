# Локальний запуск KanbanBoard

Сервер API і MSSQL запускаються через Docker Compose; Avalonia працює як нативний застосунок macOS. Базова конфігурація доступна лише з цього комп’ютера. Джерела: [рішення PH-00](PH00_DECISIONS.md), [PH-07](PHASES.md#10-ph-07--docker-та-збереження-даних), [вимоги](REQUIREMENTS.md#4-нефункціональні-вимоги).

## Передумови та секрети

Потрібні Docker Desktop із запущеним Docker Engine та .NET SDK, вибраний `global.json`, для нативного клієнта. На Apple Silicon MSSQL працює з `platform: linux/amd64` через емуляцію; це перевірена для курсової локальна конфігурація, яка не змінює [обмежень підтримки Microsoft](https://learn.microsoft.com/en-us/sql/linux/containers/deploy?view=sql-server-ver16). API використовує архітектуру Docker-хоста.

Скопіювати `.env.example` у `.env`. Встановити власний складний `MSSQL_SA_PASSWORD` і випадковий `JWT_KEY` щонайменше 32 байти, наприклад отриманий через `openssl rand -hex 32`. Пароль SQL не повинен містити подвійних лапок або знака долара; connection string використовує лапки, а Compose інтерполює змінні. Значення прикладу не є готовими секретами. `.env` виключено з Git і з контексту Docker; не публікувати його та результат `docker compose config` без `--quiet`.

Секрети передаються контейнерам як змінні середовища локального Docker; користувач із доступом до Docker може їх прочитати. Зміна `MSSQL_SA_PASSWORD` у `.env` не змінює пароль `sa` у вже створеній БД: для цього потрібна окрема SQL-операція. Зміна JWT-ключа після перевідтворення API анулює раніше видані токени.

Необов’язкові параметри: `API_PORT=5000`, `SQL_PORT=3038`, `KANBAN_DATABASE=KanbanDB`. Порти завжди публікуються на `127.0.0.1`; назву БД задавати простим ідентифікатором без роздільників connection string. Якщо порт зайнятий Rider або іншим застосунком, зупинити відповідний власний процес або вибрати інший порт у `.env`.

## Запуск і перевірка

Із кореня репозиторію:

```sh
docker compose config --quiet
docker compose up --build -d --wait --wait-timeout 240
docker compose ps
```

Стандартна команда ТЗ `docker compose up --build -d` також запускає обидва сервіси. Додатковий `--wait` повертається після їх готовності; перше завантаження образів і збірка потребують мережі й додаткового часу.

SQL healthcheck виконує `SELECT 1`; `depends_on: condition: service_healthy` затримує створення API до готовності SQL. API застосовує EF-міграції до початку приймання HTTP-запитів. Помилка міграції або невалідний JWT-ключ зупиняє цей запуск із кодом 1 до відкриття HTTP-порту; `restart: unless-stopped` повторює запуск, проте не робить помилкову конфігурацію готовою.

- `http://127.0.0.1:5000/health/live` — живий HTTP-процес.
- `http://127.0.0.1:5000/health/ready` — 200 лише за доступної БД без незастосованих міграцій, інакше 503.
- Healthcheck образу викликає `dotnet KanbanApi.dll --healthcheck` всередині контейнера на порту 8080. Окремі curl, SDK або другий сервер для цього не потрібні.

При недоступності SQL живий API може лишатися live і стати not ready. Docker позначає контейнер unhealthy після невдалих проб; сам статус unhealthy не перезапускає процес. Після відновлення SQL готовність повертається. `restart` застосовується до завершеного процесу, а не до статусу healthcheck. [Документація Docker](https://docs.docker.com/compose/how-tos/startup-order/), [health checks ASP.NET Core](https://learn.microsoft.com/en-us/aspnet/core/host-and-deploy/health-checks?view=aspnetcore-10.0).

## Нативний клієнт

```sh
KANBAN_API_URL=http://127.0.0.1:5000/ scripts/dotnet.sh run --project Curs
```

У Rider вибрати проєкт `Curs`, додати змінну середовища `KANBAN_API_URL` з тією самою адресою та запустити. Для стандартного порту адреса вже має типове значення `http://127.0.0.1:5000/`. При зміні `API_PORT` оновити адресу клієнта; SQL-порт клієнт не використовує.

Для запуску з Finder на цьому Mac:

```sh
scripts/package-macos.sh
open TestResults/KanbanBoard.app
```

Скрипт створює локальний `.app` з іконкою KanbanBoard (`Contents/Resources/kanbanboard.icns`, `CFBundleIconFile`) та нативним apphost, який macOS коректно пов’язує з вікном. Якщо SDK встановлено в `.tools/dotnet`, збірка знаходить цей runtime відносно `TestResults`; зберігати це розташування під час запуску. Збірка з глобальним SDK використовує встановлений runtime .NET 10. Застосунок і результати збірки виключені з Git. Типова IPv4-адреса запобігає потраплянню до системного AirPlay на IPv6-порту 5000 після розриву з’єднання.

За потреби підготувати демонстраційні дошки й вигаданих учасників: `python3 scripts/seed-demo.py`. Генератор використовує звичайний API, фото з `assets/demo` і зберігає локальні дані входу лише в ігнорованому `TestResults/ph08-demo.json`. Фото й профілі зберігаються в тому самому SQL volume.

## Зупинка та збереження

```sh
docker compose stop
docker compose start --wait
```

Для видалення контейнерів і мережі зі збереженням даних:

```sh
docker compose down
docker compose up -d --wait --wait-timeout 240
```

Іменований volume `kanbanboard_sqlserver-data` зберігає всі дев’ять таблиць, оригінали й превью фото. Повторне створення API або SQL-контейнера та оновлення образу не повинні видаляти цей volume. `docker compose down -v` видаляє БД — це не штатна зупинка. Не змінювати Compose project name для звичайного запуску: інша назва створює інший volume. Volume не замінює резервне копіювання.

Перегляд стану: `docker compose ps`, журнали: `docker compose logs --tail 100 api sqlserver`. Не публікувати журнали без перевірки на приватні дані. Для перевірки відтворюваності ізольовано від робочої БД:

```sh
python3 scripts/verify-ph07-docker.py
```

Скрипт створює випадковий Compose-проєкт із новими секретами, вільними loopback-портами та власним volume. Перевіряє чисту БД, міграції, CRUD/порядок/фото, перезапуск, down/up, втрату SQL і помилки запуску. Наприкінці прибирає лише власні контейнери та власний тимчасовий volume. Для ручної перевірки клієнта параметр `--gui` залишає цей стенд працювати до переривання; адресу виведено та збережено у виключеному з Git `TestResults/ph07-gui.env`.

## Склад образу

`KanbanApi/Dockerfile` використовує два етапи: SDK 10.0.103 для Release-публікації та ASP.NET runtime 10.0.13 для запуску. Публікація обмежена `linux-$TARGETARCH`, тож сторонні ОС і архітектури Magick.NET не потрапляють у готовий сервер. Відновлення залежностей, публікація та видалення кешу NuGet виконуються в одному шарі: це прибирає великий кеш пакетів із проміжного шару при малому диску Docker. Повторна збірка зміненого коду може знову завантажувати пакети. Обидва образи зафіксовані digest; перевірений образ MSSQL лишається зафіксованим у Compose. Контекст — корінь репозиторію через залежність `KanbanContracts`. `.dockerignore` пропускає лише сервер, контракти та `global.json`, відсікаючи навіть їхні `bin`/`obj`. Ні `.env`, ні клієнт, ні тести не потрапляють у збірку.

Сервер запускається як вбудований непривілейований користувач образу, на порту 8080. Фото зберігаються у MSSQL, тому API не потребує окремого volume. Обрано звичайний Linux runtime із підтримкою нативного Magick.NET; усі формати потрібно перевіряти у контейнері, а не лише на macOS. [Офіційний приклад контейнеризації .NET](https://learn.microsoft.com/en-us/dotnet/core/docker/build-container).

## Оновлення від 17.10.2026

Профіль → «Видалити мій аккаунт» → переглянути наслідки → ввести поточний email і пароль → «Запланувати видалення». Застосунок завершить сеанси та покаже кінцеву дату. **Вхід протягом 7 днів автоматично скасовує видалення.** До завершення строку аккаунт і вміст дощок зберігаються в БД. Чотири демонстраційні аккаунти захищені від цієї дії.

Після 7 днів фоновий сервіс очищає прострочені аккаунти: спільні дошки передає учаснику, особисті дошки без інших учасників видаляє. Перевірка виконується при старті API та щохвилини; якщо API був вимкнений, очистка продовжується після наступного запуску. Вхід після кінцевої дати не відновлює аккаунт, навіть якщо черговий цикл очищення ще не завершився.

Після оновлення: `docker compose up -d --build --wait`, щоб застосувати чотири поточні міграції; потім перезапустіть клієнт. Для іконки macOS: `scripts/package-macos.sh`, відкрити `TestResults/KanbanBoard.app` із Finder. Третя міграція дозволяє відсутнього автора історії; четверта додає строк відновлення та захист demo. Дані дощок цими міграціями не очищаються. Downgrade зі збереженим періодом відновлення або вже анонімізованою історією відхиляється.

Збірка API не зберігає дубль HTTP-кэшу NuGet і відкидає нативні бібліотеки інших платформ перед публікацією, щоб зменшити витрату диска Docker при ліміті 7,8 ГіБ. Застарілий кэш збірок іноді потребує очищення; робочий volume `kanbanboard_sqlserver-data` зберігається. [Результати перевірок](PH08_ACCOUNT_ICON.md).

## Привітання та автоматичний вхід

На macOS увімкніть «Запам’ятати мене» перед успішним входом. При наступному запуску застосунок перевірить сеанс і відкриє дошки; «Вийти» очистить локальне збереження. Щоб змінити аккаунт, вийдіть, за потреби вимкніть тумблер та введіть інші дані. Пароль не записується; токен та email захищає В’язка ключів macOS. Після завершення 24 годин або відкликання сеансу потрібен повторний вхід. Недоступний сервер дозволяє повторити автоматичний вхід; можна також відмовитися від запам’ятовування. [Деталі й перевірки](PH08_WELCOME.md).
