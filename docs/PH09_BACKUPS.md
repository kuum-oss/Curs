# PH-09 — резервна копія дошки, відновлення та CSV

Виконано 21.10.2026 як **окремий етап надійності після календаря**. Користувач погодив копію вибраної дошки й відновлення в нову. [Концепт](concepts/BOARD_BACKUP.md) створений до коду (`8ce28aa`). [Протокол](PH09_BACKUPS_RESULTS.json), [нативні скриншоти](screenshots/backups/README.md).

## Функції

«Резервні копії»: виберіть дошку, збережіть `.kanban.json` або список задач у CSV. Копія містить назву/опис/архівність дошки, обкладинку; колонки й порядок; активні/архівні картки з описом, строком, пріоритетом, порядком і датами; теги/зв’язки; впорядковані чек-листи; коментарі з текстом, історичним автором і датами; оригінали фото. Превью при відновленні перераховуються перевіреним декодером.

Виберіть файл, перегляньте склад, натисніть «Відновити як нову дошку», потім «Відкрити дошку». Відновлення не змінює оригінал. Усі внутрішні ключі нові; користувач стає власником/адміністратором. Учасники, їхні ролі й обмеження не додаються автоматично. Ім’я попереднього виконавця зберігається в `SourceAssigneeName` й показується в редакторі, але живе призначення відсутнє. При новому призначенні історична підказка очищується. Імпортований коментар має `SourceAuthorName`, нейтральний AuthorId і позначку «з копії», його текст незмінний. Це не видає його за нову дію оригінального автора. Додаткове відновлення з новою операцією свідомо може створити ще одну копію.

Копія не включає аккаунти, паролі, JWT, аватари профілів, особисті чати, сповіщення, обране чи історію відвідувань. Файл не шифрується; це логічна копія дошки, не повний `.bak` SQL Server. Контрольна сума виявляє пошкодження, але не є цифровим підписом або доказом авторства. Ліміти: 32 МіБ JSON, 5000 карток, 200 колонок, 500 тегів, 20 000 коментарів, 100 пунктів і 100 тегів на картку, 20 МіБ сумарних оригіналів фото та 5 МіБ на одне фото. Великі запити мають до 120 секунд; звичайні клієнтські запити зберігають 10-секундний timeout. Скасування не відновлює дані сеансу після виходу.

## Формат і API

JSON v1: `format: KanbanBoard`, `version: 1`, `createdAtUtc`, `checksum` і типізований `data`. SHA-256 рахується по канонічній JSON-серіалізації типізованого data. Порядок колонок/карток/пунктів нормалізується зі збереженням відносного порядку. Імпорт перевіряє ключі, зв’язки, унікальність, поля, обсяги й фото до запису. Жоден ID автора з файлу не отримує повноважень. Збереження всього графа — одна транзакція. Повтор того самого operationId обмежений користувачем і повертає ту саму дошку; інший вміст дає 409. Навіть два одночасні повтори не дублюють дошку.

| Метод | Шлях | Результат |
| --- | --- | --- |
| GET | `/api/boards/{id}/backup` | JSON доступної дошки, включно з архівом |
| GET | `/api/boards/{id}/export.csv` | UTF-8 BOM, кома, CRLF, один рядок на задачу |
| POST | `/api/backups/restore` | `{operationId, backup}` → `{boardId, alreadyRestored}` |

CSV: ID, назва, опис, дошка, колонка, дедлайн, пріоритет, ім’я виконавця, теги, прогрес чек-листа, архівність, дати UTC. Усі поля цитуються; лапки подвоюються, коми/переноси зберігаються. Потенційні формули нейтралізуються префіксом апострофа. CSV не призначений для відновлення повного графа.

Дев’ята міграція `20261021153418_BoardBackupMetadata`: nullable `Boards.RestoreChecksum`, `Cards.SourceAssigneeName`, `Comments.SourceAuthorName`; наявні дані збережені, таблиць **13**. Downgrade з імпортованими відомостями відхиляється SQL 50009. Після часткового відкату іншого старого сценарію міграцій тест перевіряє лише поля, які існують на цій версії схеми.

## Перевірки

**190 тестів із реальною MSSQL, 0 помилок і пропусків.** Додано 4 серверні, 1 міграційний і 2 клієнтські. Покриті повний граф/архів/обкладинка/фото/чек-лист/коментарі, історичні імена без членства, конкурентний повтор, пошкодження/неправильні зв’язки/недопустимі фото без часткового запису, зміна вмісту повтору, доступ, формат CSV/Unicode/формули, втрата відповіді після commit, скасування та вихід під час вибору файла. Після фінальної перевірки меж експорту повторно пройшли 7 профільних тестів. Release/macOS publish без попереджень/помилок, змін моделі поза міграцією немає.

25 запитів Docker API перевірили round trip фото, чек-листа й коментарів, повтор без дубля, відсутність секретів і неявного членства, CSV, пошкоджену копію та анонімний запит. Нативний CUA: системний Save для JSON/CSV, Open для щойно збереженої копії, попередній перегляд, третя нова дошка, кнопка відкриття, фото/дедлайн/тег/прогрес/історичні імена в редакторі. Збережені файли розібрані, нова дошка звірена через API; оригінальна дошка з двома учасниками лишилася незмінною. Випадкові 2 аккаунти та 3 дошки після перевірки прибрані; захищені demo не використовувалися для змін.

Ключові коміти: `703857e` — сервер/міграція; `2a36d38` — нативний клієнт. [Вимоги](REQUIREMENTS.md#14-резервні-копії-та-csv--21102026), [реалізація](IMPLEMENTATION.md#14-резервні-копії-та-csv--21102026), [запуск](DEPLOYMENT.md#календар-резервні-копії-та-csv), [фази](PHASES.md).
