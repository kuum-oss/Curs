# Правила роботи з KanbanBoard

## Коміти та завершення фаз

Ці правила задані користувачем 11.10.2026 та застосовуються до наступних робіт у цьому репозиторії.

- Після кожної завершеної логічної зміни коду, документації або конфігурації створювати окремий тематичний коміт. Не відкладати всі зміни до одного коміту наприкінці фази.
- Перевіряти результат відповідними до зміни засобами до коміту. Читання файлів і перевірки без змін не потребують порожніх комітів.
- Після завершення фази оновлювати її статус та докази у `docs/PHASES.md`, закомітити це оновлення й виконати push до налаштованого GitHub remote.
- Публікацію вважати підтвердженою лише після перевірки, що віддалена гілка містить той самий коміт, що й локальний HEAD. Невдалий push не означає завершення публікації.
- Якщо push неможливий, зберегти локальні коміти та повідомити точну причину; не переписувати віддалену історію через force push.
- Додавати до комітів лише файли відповідного завдання. Не включати локальні секрети, результати збірки або сторонні зміни користувача.
- Для наступних фаз ці дії вже авторизовані користувачем; повторного дозволу на звичайні тематичні коміти та push після завершення фази не потрібно.
