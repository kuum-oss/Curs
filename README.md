# KanbanBoard — курсова робота

Клієнт-серверна десктопна система для командного планування завдань за Kanban-методологією. Користувачі працюють зі спільними дошками, колонками та картками через клієнт Avalonia UI.

## Поточний стан

Стан на 15.10.2026: PH-00–PH-07 виконано. Рішення `Curs.sln` містить Avalonia-клієнт `Curs`, сервер `KanbanApi`, спільні DTO `KanbanContracts` та тести `KanbanApi.Tests`. Використовуються .NET 10, Avalonia 11.3.12 та EF Core 10.0.12.

Початкова міграція створила дев'ять таблиць у справжньому MSSQL 2022. API має перевірки працездатності та єдиний формат помилок; клієнт — основу MVVM, HTTP, сесії та навігації. У PH-01 Release-збірка пройшла без попереджень; усі 19 початкових тестів пройшли без пропусків. Докази — у [результатах PH-01](docs/PH01_IMPLEMENTATION.md) та [протоколі](docs/PH01_RESULTS.json).

PH-02 додала реєстрацію, вхід, BCrypt-хеші та JWT на 24 години. У Avalonia працюють форми авторизації та вихід; токен зберігається лише в пам’яті. [Звіт PH-02](docs/PH02_AUTHENTICATION.md).

PH-03 реалізувала список, створення, редагування та видалення дощок, додавання й відкликання учасників, зміну дозволів. API перевіряє актуальні права та версію дошки; зміни виконуються атомарно. Результат цієї фази: 49 тестів пройшли без пропусків, з них 30 на MSSQL; 27 нативних HTTP-перевірок; сценарії адміністратора й учасника перевірені в живому Avalonia; Release без попереджень. [Звіт і скриншоти PH-03](docs/PH03_BOARDS.md).

PH-04 додала керування колонками й картками, теги, відповідального, дедлайн, пріоритет та коментарі. Обмеження створення/видалення діють у UI і API; конфлікт зберігає чернетку, видалення атомарне. Поточний результат: 64 тести без помилок/пропусків, з них 44 на MSSQL; 74 нативні HTTP-перевірки; живий Avalonia; Release без попереджень. [Звіт PH-04](docs/PH04_CONTENT.md).

PH-05 додала перетягування карток і колонок, атомарні позиції, відкат при помилці та оновлення відкритої дошки кожні 5 секунд зі збереженням чернеток. Поточний результат: 80 тестів, з них 53 на MSSQL, 116 нативних HTTP-перевірок, перевірка двох вікон і Release без попереджень. [Звіт PH-05](docs/PH05_COLLABORATION.md).

PH-06 додала пошук і всі фільтри з AND, скасування застарілого запиту, повну пагінацію та захищені обкладинки JPG/PNG/WEBP до 5 МіБ. Превью видно на картці, повний файл — у редакторі; кеш очищається при виході й втраті доступу. Поточний результат: 93 тести (60 на MSSQL), 211 HTTP-перевірок, два живі вікна та Release без попереджень. [Звіт PH-06](docs/PH06_FILTERS_IMAGES.md).

PH-07 додала багатостадійну Docker-збірку API, readiness, контрольований вихід при помилці запуску та повний запуск Compose. Перевірено чисту БД, restart/down/up, відновлення після зупинки SQL й нативний клієнт: 26 перевірок розгортання та 82 HTTP-запити; 93 тести й Release без попереджень. [Звіт PH-07](docs/PH07_DOCKER.md).

Наступна фаза — PH-08: приймання, навантаження та матеріали захисту.

## Межі проєкту

- Єдиний користувацький інтерфейс — десктопний застосунок Avalonia.
- Розгортання локальне; хмарний деплой не входить до завдання.
- Сервер і база даних мають запускатися через Docker Compose.
- Користувач погодив нативний клієнт та API/БД у Docker. Базовий запуск — на одному Mac; 20 користувачів моделюються в тесті. Обрано практичну перевірку MSSQL 2022 через емуляцію `linux/amd64`.

## Підготовка локального середовища

Потрібен запущений Docker Desktop. Скопіювати `.env.example` у `.env`, встановити власний складний пароль MSSQL та випадковий JWT-ключ щонайменше 32 байти. Наявний `.env` не перезаписувати: зміна файлу не змінює пароль у вже створеній БД. Повна інструкція — [DEPLOYMENT](docs/DEPLOYMENT.md).

```sh
docker compose config --quiet
docker compose up --build -d --wait --wait-timeout 240
```

API автоматично застосовує міграції до приймання запитів. Перевірки `http://127.0.0.1:5000/health/live` та `http://127.0.0.1:5000/health/ready` мають повернути 200. Порти 5000/3038 доступні лише на цьому комп’ютері. MSSQL 2022 працює через перевірену для курсової емуляцію linux/amd64 на поточному ARM Mac; [результати PH-00](docs/PH00_ENVIRONMENT.md) пояснюють обмеження середовища.

Для нативного клієнта потрібен повний .NET SDK 10.0.103 або сумісний patch за `global.json`. `scripts/dotnet.sh` використовує локальний SDK з `.tools/dotnet`, якщо він є, інакше системний; скрипт не завантажує SDK. У Rider вибрати Curs та той самий SDK.

```sh
KANBAN_API_URL=http://127.0.0.1:5000/ scripts/dotnet.sh run --project Curs
```

Штатна зупинка — `docker compose stop` або `docker compose down` без `-v`. Іменований volume зберігає всі дані та фото; `docker compose down -v` видаляє БД. Повторний запуск — `docker compose up -d --wait --wait-timeout 240`.

Перевірка збірки, тестів на MSSQL та окремого тимчасового Docker-стенда:

```sh
scripts/dotnet.sh build Curs.sln -c Release
python3 scripts/verify-ph01.py ph07
python3 scripts/verify-ph07-docker.py
```

SQL-тести створюють тимчасові БД та прибирають їх; без `KANBAN_TEST_CONNECTION` прямий dotnet test пропускає SQL-сценарії, тому використовувати наведений wrapper. Docker-скрипт створює власний випадковий проєкт, секрети, порти й volume; робочий volume не видаляє. Параметр `--gui` залишає тестовий стенд до переривання, адресу друкує та записує у TestResults/ph07-gui.env.

Для нативної розробки сервера зупинити контейнер API (`docker compose stop api`), залишити SQL і запустити `scripts/dotnet.sh run --project KanbanApi`. Development читає локальний `.env`; поза ним потрібні ConnectionStrings__Default і Jwt__Key/JWT_KEY. Старий нативний HTTP-сценарій PH-06 доступний через `python3 scripts/verify-ph06-http.py` після Debug-збірки.

Послідовність робіт і питання, які залишаються відкритими, наведені в [плані реалізації](docs/IMPLEMENTATION.md).
