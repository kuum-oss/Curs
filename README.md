# KanbanBoard — курсова робота

Клієнт-серверна десктопна система для командного планування завдань за Kanban-методологією. Користувачі працюють зі спільними дошками, колонками та картками через клієнт Avalonia UI.

## Поточний стан

Стан на 12.10.2026: PH-00–PH-05 виконано. Рішення `Curs.sln` містить Avalonia-клієнт `Curs`, сервер `KanbanApi`, спільні DTO `KanbanContracts` та тести `KanbanApi.Tests`. Використовуються .NET 10, Avalonia 11.3.12 та EF Core 10.0.12.

Початкова міграція створила дев'ять таблиць у справжньому MSSQL 2022. API має перевірки працездатності та єдиний формат помилок; клієнт — основу MVVM, HTTP, сесії та навігації. У PH-01 Release-збірка пройшла без попереджень; усі 19 початкових тестів пройшли без пропусків. Докази — у [результатах PH-01](docs/PH01_IMPLEMENTATION.md) та [протоколі](docs/PH01_RESULTS.json).

PH-02 додала реєстрацію, вхід, BCrypt-хеші та JWT на 24 години. У Avalonia працюють форми авторизації та вихід; токен зберігається лише в пам’яті. [Звіт PH-02](docs/PH02_AUTHENTICATION.md).

PH-03 реалізувала список, створення, редагування та видалення дощок, додавання й відкликання учасників, зміну дозволів. API перевіряє актуальні права та версію дошки; зміни виконуються атомарно. Результат цієї фази: 49 тестів пройшли без пропусків, з них 30 на MSSQL; 27 нативних HTTP-перевірок; сценарії адміністратора й учасника перевірені в живому Avalonia; Release без попереджень. [Звіт і скриншоти PH-03](docs/PH03_BOARDS.md).

PH-04 додала керування колонками й картками, теги, відповідального, дедлайн, пріоритет та коментарі. Обмеження створення/видалення діють у UI і API; конфлікт зберігає чернетку, видалення атомарне. Поточний результат: 64 тести без помилок/пропусків, з них 44 на MSSQL; 74 нативні HTTP-перевірки; живий Avalonia; Release без попереджень. [Звіт PH-04](docs/PH04_CONTENT.md).

PH-05 додала перетягування карток і колонок, атомарні позиції, відкат при помилці та оновлення відкритої дошки кожні 5 секунд зі збереженням чернеток. Поточний результат: 80 тестів, з них 53 на MSSQL, 116 нативних HTTP-перевірок, перевірка двох вікон і Release без попереджень. [Звіт PH-05](docs/PH05_COLLABORATION.md).

Наступна фаза — PH-06: пошук, фільтри та фото. Dockerfile API буде додано у PH-07; зараз SQL запускається через Compose, API — нативно.

## Межі проєкту

- Єдиний користувацький інтерфейс — десктопний застосунок Avalonia.
- Розгортання локальне; хмарний деплой не входить до завдання.
- Сервер і база даних мають запускатися через Docker Compose.
- Користувач погодив нативний клієнт та API/БД у Docker. Базовий запуск — на одному Mac; 20 користувачів моделюються в тесті. Обрано практичну перевірку MSSQL 2022 через емуляцію `linux/amd64`.

## Підготовка локального середовища

Перевірити [результати PH-00](docs/PH00_ENVIRONMENT.md) для цільової машини. За відсутності `.env` скопіювати `.env.example` у `.env` та задати локальні секрети. Під час цієї фази `.env` вже створено з випадковими значеннями; він не відстежується Git.

```sh
docker compose config --quiet
docker compose up -d sqlserver
```

Потрібен повний .NET SDK 10.0.103 або сумісний patch відповідно до `global.json`. `scripts/dotnet.sh` використовує локальний SDK з `.tools/dotnet`, якщо він є, інакше системний `dotnet`. Скрипт не завантажує SDK. На поточному Mac використано повний локальний SDK, оскільки системна інсталяція не містила потрібних reference packs. Для Rider можна вибрати цей самий SDK.

Після готовності SQL запустити API:

```sh
scripts/dotnet.sh tool restore
scripts/dotnet.sh run --project KanbanApi
```

У Development API читає локальний пароль SQL та `JWT_KEY` з `.env` і застосовує міграції до `KanbanDB` перед запуском. Поза Development потрібно передати `ConnectionStrings__Default` та `JWT_KEY` або `Jwt__Key`. Шаблонний JWT-секрет необхідно замінити випадковим значенням щонайменше на 32 байти. Перевірки: `http://localhost:5000/health/live` та `http://localhost:5000/health/ready`; обидві мають повернути HTTP 200.

В іншому терміналі запустити клієнт; адресу сервера можна змінити через `KANBAN_API_URL`:

```sh
scripts/dotnet.sh run --project Curs
```

Перевірка збірки та тестів на реальному SQL:

```sh
scripts/dotnet.sh build Curs.sln -c Release
python3 scripts/verify-ph01.py ph05
```

Для окремої перевірки нативного API після Debug-збірки виконати `python3 scripts/verify-ph05-http.py`. Параметр `--gui` залишає API на `http://127.0.0.1:5045` для ручної перевірки клієнта з `KANBAN_API_URL=http://127.0.0.1:5045/`; після закриття клієнта перервати скрипт, щоб він прибрав тимчасову БД.

SQL-тести створюють окрему тимчасову БД та прибирають її після виконання. Звичайний запуск тестів без `KANBAN_TEST_CONNECTION` пропускає SQL-сценарії; для повної перевірки використовувати наведений скрипт. Повний `docker compose up --build -d` стане доступним після створення Dockerfile у PH-07.

Послідовність робіт і питання, які залишаються відкритими, наведені в [плані реалізації](docs/IMPLEMENTATION.md).
